# 게임 기획서: 적재 퍼즐 (가제: "꽉 잡아, 배달!")

- 버전: v0.1 (MVP 검증판)
- 작성일: 2026-07-27
- 팀: 3명 (전원 Unity 초급)
- 목적: 게임잼식 빠른 재미 검증 (~1개월)

---

## 1. 게임 개요

| 항목 | 내용 |
|---|---|
| 장르 | 물리 기반 적재 퍼즐 |
| 시점 | 폴리브릿지식: **3D 로우폴리 그래픽 + 측면 카메라** (게임플레이는 단일 평면에서 진행) |
| 엔진 | **Unity (3D 프로젝트, 로우폴리 아트)** |
| 플랫폼 | **PC (itch.io / Steam)** - 마우스 조작 기준 |
| 플레이 인원 | 싱글 플레이 |
| 목표 플레이타임 | 스테이지당 3~5분, MVP 전체 10~15분 |

### 컨셉 한 줄 요약
짐을 트럭 짐칸에 잘 쌓고 시작 버튼을 누르면, 차가 정해진 경로를 자동 주행한다. 짐을 떨어뜨리지 않고 목적지에 도달하면 승리.

### 핵심 차별점
- 플레이어는 **운전하지 않는다**. 게임의 실력 요소는 전부 적재 단계에 있고, 주행 단계는 내 선택의 결과를 지켜보는 관전 페이즈다.
- 짐이 떨어지는 것은 스크립트가 아니라 **물리 엔진의 관성**으로 자연스럽게 일어난다. 급가속, 경사, 착지 충격이 짐을 흔든다.
- **카메라 연출**: 적재 단계에서는 카메라가 **트럭 짐칸으로 확대(클로즈업)** 되어 짐을 쌓는다. 시작 버튼을 누르면 카메라가 뒤로 빠지며 경로가 보이는 측면 와이드 뷰로 전환된다. 폴리브릿지의 "건설 → 시뮬레이션" 전환과 같은 리듬.

## 2. 핵심 게임 루프

```
[경로 확인] → [적재] → [시작 버튼] → [자동 주행 관전] → [결과/재도전]
```

1. **경로 확인**: 스테이지 시작 시 주행 경로 전체(경사, 방지턱, 점프대 위치)를 보여준다. 플레이어는 경로를 읽고 대비한다.
2. **적재**: 카메라가 트럭 짐칸으로 확대된 상태에서, 마우스 드래그로 짐을 짐칸에 배치한다. 이 게임의 핵심 조작이자 실력 요소.
3. **시작**: 버튼을 누르면 적재 조작이 잠기고, 카메라가 측면 와이드 뷰로 빠지며 차가 출발한다.
4. **관전**: 차는 정해진 속도 프로필로 일자 경로를 자동 주행한다. 짐은 자유 리지드바디로 물리에 맡겨진다.
5. **결과**: 도착 시 남은 짐 수에 따라 점수(별)를 부여. 실패해도 즉시 재도전 가능해야 한다.

## 3. MVP 범위 (확정)

### 3.1 짐 3종

| 짐 | 물리 특성 | 배치 대응법 |
|---|---|---|
| 일반 상자 | 기본 마찰, 사각형 | 기준 짐. 벽에 밀착, 아래 깔기 |
| 원통 | 굴러감 (눕힌 원기둥) | 눕히는 방향 결정, 상자 사이에 끼우기, 로프로 묶기 |
| 깨지기 쉬움 (유리 상자) | 일정 충격 이상 받으면 파손 | 맨 위 배치, 주변 비우기, 로프로 고정 |

**설계 원칙**: 모든 스테이지는 **배치만으로** 해결한다. 고정 장비는 MVP에 없다. 게임의 실력 요소는 "무엇을 어디에 어떤 방향으로 쌓느냐" 하나로 압축된다.

### 3.2 적재 조작 (핵심 조작이므로 별도 명시)

- 마우스 드래그로 짐을 집어 짐칸 위에 놓는다
- 배치 중 고스트(반투명 미리보기) 표시, 배치 불가 위치(겹침 등)는 색으로 구분
- R 키(또는 우클릭)로 90도 회전: 원통을 눕힐지 세울지가 전략이 된다
- 시작 전까지는 몇 번이든 다시 집어 재배치 가능

### 3.3 스테이지 3개

| # | 컨셉 | 경로 요소 | 짐 구성 |
|---|---|---|---|
| 1 | 튜토리얼: 쌓고 출발 | 평지 + 완만한 오르막 | 상자 3개 |
| 2 | 굴러가는 녀석 | 평지 + 방지턱 2개 | 상자 2 + 원통 1 |
| 3 | 깨지기 쉬운 배달 | 오르막 + 내리막 + 급제동 | 상자 2 + 원통 1 + 유리 1 |

### 3.4 명시적 제외 목록 (MVP에서 만들지 않음)

- 나머지 짐 속성: 미끄러움, 튀어오름, 살아있음
- 고정 장비 전종: 로프, 쐐기, 고무 매트, 그물, 완충 폼, 우리 (전부 확장 로드맵으로)
- 월드/챕터 개념 (스테이지 번호만)
- 모바일 / WebGL 빌드
- 주행 중 1회성 개입 (클램프/에어백 버튼) - 보류 카드로만 유지
- 상점, 스킨, 수집 요소, 클라우드 세이브

## 4. 시스템 상세

### 4.1 물리 설계 (Unity 3D + 단일 평면 게임플레이)

폴리브릿지 방식을 따른다: 그래픽은 3D 로우폴리지만, 물리 게임플레이는 한 평면 위에서만 일어난다. 3D `Rigidbody`에 제약(Constraints)을 걸어 2D처럼 동작시킨다. 초급 팀이 3D 물리의 자유도를 전부 다루지 않아도 되게 하는 핵심 장치다.

- **평면 고정**: 모든 짐의 `Rigidbody`에 `Freeze Position Z` + `Freeze Rotation X/Y`를 설정한다. 짐은 화면 평면 안에서만 미끄러지고 기울어진다 (깊이 방향으로는 절대 이동하지 않음)
- 짐: `Rigidbody` + `BoxCollider`(상자/유리) / 눕힌 `CapsuleCollider` 또는 `MeshCollider`(원통). 트럭과 조인트 연결 없이 짐칸 위에 올려놓기만 한다
- 트럭: 정해진 속도 프로필로 이동. MVP에서는 바퀴 물리 대신 **경로를 따라 이동하는 키네마틱 차체 + 짐칸만 물리 충돌** 방식도 허용 (초급 팀 난이도 고려, 프로토타입에서 둘 다 시험 후 결정)
- 마찰: 짐칸 바닥과 짐에 각각 `Physic Material`을 만들어 마찰계수를 독립 튜닝. **이 튜닝이 게임 재미의 8할이므로 인스펙터에서 실시간 조정 가능한 디버그 패널을 만든다**
- 카메라: 적재(짐칸 클로즈업) ↔ 주행(측면 와이드, 트럭 추적) 두 상태를 부드럽게 전환. Cinemachine 가상 카메라 2개 전환이면 초급 팀도 구현 가능
- 안정성: Fixed Timestep 조정(0.01~0.02), 짐 간 질량 비율 10:1 이내 유지

### 4.2 판정

- **낙하 판정**: 짐칸 위 트리거 영역(Trigger Collider)을 벗어나면 "떨어짐" 카운트
- **파손 판정**: 유리 상자는 `OnCollisionEnter`의 상대 충격량(relativeVelocity)이 임계값 초과 시 파손
- **클리어 판정**: 차가 도착 지점 통과 시, 남은 짐 수 집계

### 4.3 점수

| 별 | 조건 (기본안) |
|---|---|
| ★ | 짐 1개 이상 도착 |
| ★★ | 짐 전부 도착 |
| ★★★ | 짐 전부 도착 + 유리 무파손 |

### 4.4 UI (최소)

- 적재 화면: 짐칸 클로즈업 카메라. 짐 목록(드래그 소스), 경로 미리보기 버튼, 시작 버튼
- 주행 화면: 측면 와이드 카메라가 트럭 추적, 남은 짐 카운터
- 결과 화면: 별, 재도전 / 다음 스테이지 버튼

세부 레이아웃은 그레이박스로 시작하고, 재미 검증 통과 후에 다듬는다.

## 5. 제작 계획 (4주)

| 주차 | 목표 | 진행 방식 | 완료 기준 |
|---|---|---|---|
| 1주 | 물리 프로토타입 | **전원 공동 작업** (분담 없음) | 상자를 쌓고 트럭이 이동하면 관성으로 짐이 흔들리고 떨어진다. 인터페이스 이벤트 합의 완료 |
| 2주 | 핵심 루프 완성 | 역할 분담 시작 | 적재 → 주행 → 낙하/클리어 판정 → 결과 화면이 이어진다. 스테이지 1 완성 |
| 3주 | 콘텐츠 | 역할 분담 | 원통/유리 추가, 스테이지 2~3 완성 |
| 4주 | 튜닝/빌드 | 전원 플레이테스트/밸런싱 | 마찰·난이도 튜닝, 효과음/이펙트 최소치, itch.io 빌드 업로드, 외부 테스트 |

1주 차를 분담하지 않는 이유: 전원 초급이라 이 시점엔 속도보다 공통 이해가 중요하고, 물리 프로토타입을 같이 만들어야 이후 서로의 코드를 읽을 수 있다. 이 게임은 1주 차 결과물이 "재미있을 조짐"을 보여야 하므로 가장 중요한 주에 병렬화로 시간을 아낄 이유가 없다.

### 역할 분담 (2주 차부터)

**A - 짐/물리 담당**
- 짐 프리팹 3종 (상자/원통/유리), Rigidbody 제약 설정, Physic Material
- **마우스 드래그 배치 시스템 (게임의 핵심 조작: 고스트 미리보기, 회전, 재배치)**
- 낙하 판정(트리거 영역), 유리 파손 판정
- 마찰/질량 실시간 튜닝 디버그 패널

**B - 게임 플로우/UI 담당**
- GameManager 상태 머신: 적재 → 주행 → 결과 (게임의 등뼈)
- Cinemachine 카메라 전환 (짐칸 클로즈업 ↔ 측면 와이드)
- UI 전부 (짐 목록, 로프 카운터, 시작 버튼, 결과 화면, 별 점수)
- 스테이지 로딩/재시작

**C - 트럭/레벨 담당**
- 트럭 이동 (경로 따라가기 + 속도 프로필: 가속/감속 구간)
- 스테이지 3개 지형 제작 (평지, 방지턱, 경사)
- 그레이박스 아트, 무료 로우폴리 팩 적용
- 플레이테스트와 난이도 튜닝 주도

**병목 주의**: B의 상태 머신과 카메라 전환이 A, C 작업의 합류 지점이다. 2주 차 초반에 B는 화려한 UI보다 상태 전환 뼈대부터 만들어 A와 C가 자기 파트를 끼워볼 수 있게 한다.

### 협업 규칙 (초급 팀 필수)

Unity 팀 작업에서 가장 크게 데이는 것은 코드가 아니라 **씬(Scene) 병합 충돌**이다. 씬 파일은 git 자동 병합이 잘 안 되므로:

1. **씬마다 주인 한 명**: 메인 게임 씬의 주인은 B. A와 C는 씬을 직접 수정하지 않고 **프리팹으로만** 기여한다 (A는 짐 프리팹, C는 레벨 프리팹을 만들어 전달)
2. **인터페이스 이벤트를 1주 차에 합의**: 세 사람의 코드가 만나는 접점을 이벤트로 고정한다. 최소 세트:
   - `OnLoadingComplete` (B → C: 적재 끝, 출발해)
   - `OnCargoDropped` (A → B: 짐 하나 떨어짐)
   - `OnTruckArrived` (C → B: 도착, 결과 화면 띄워)
3. **주 2회 정기 통합**: 정해진 요일(예: 수/토)에 전원 최신을 받아 함께 빌드한다. "마지막 주에 합치기"는 실패 공식
4. **git 세팅**: Unity용 `.gitignore` (Library/, Temp/ 등 제외) 필수, Asset Serialization은 Force Text 유지

### 검증 기준 (게임잼식이므로 명시)

4주 차 외부 테스트에서 확인할 질문:
1. 적재 단계에서 고민이 생기는가? (배치에 정답이 하나뿐이면 실패)
2. 주행 관전이 긴장되는가? (결과가 뻔하면 실패)
3. 실패했을 때 "다시 하고 싶다"가 나오는가?

통과 시 → 확장 로드맵 진행. 미달 시 → 원인 분석 후 피벗 또는 종료.

## 6. 검증 후 확장 로드맵 (참고용, MVP 아님)

1. 짐 속성 추가: 미끄러움 → 튀어오름 → 살아있음 순 (살아있음은 비용이 가장 크므로 마지막)
2. 고정 장비 추가: 새 속성으로 먼저 고생시킨 뒤 카운터 장비(로프/쐐기/고무 매트/그물/완충 폼/우리)를 해금하는 리듬. 로프가 첫 장비 후보
3. 욕심 메커니즘: 실은 만큼 보수, 전부 실을 필요 없음
4. 주행 중 1회성 개입: 배치만으로 완벽 대비가 불가능한 후반 구간에서 해금 (보류 카드)
5. 월드 구성, 모바일 포팅 검토

## 7. 리스크

| 리스크 | 대응 |
|---|---|
| 물리 튜닝 난항 (짐이 안 떨어지거나 다 쏟아짐) | 1주 차부터 마찰/질량 디버그 패널 확보, 튜닝 전담(C) 지정 |
| 초급 팀의 Unity 물리 학습 비용 | Rigidbody Constraints로 평면 고정해 사실상 2D 문제로 축소, 트럭 키네마틱 대안 유지, 조인트류는 MVP에서 사용하지 않음 |
| 3D 로우폴리 아트 부담 | MVP는 프리미티브(큐브/실린더) + 에셋 스토어 무료 로우폴리 팩으로 대체, 아트 투자는 재미 검증 통과 후 |
| 스택 떨림(jitter) 등 물리 불안정 | Fixed Timestep 조정, 질량 비율 10:1 이내, 스테이지 짐 개수 6개 이하 유지 |
| 4주 초과 | 제외 목록을 늘리는 방향으로만 조정 (스테이지 3개가 마지노선) |
